# AIを活用したEC事業分析

**[SQL](sql/) · [ノートブック](analysis/customer_product_analysis.ipynb) · [ダッシュボード](dashboard/index.html) · [1ページサマリー](presentation/summary.md) · [データについて](data/README.md)**

*[Read in English](README.md)*

EC事業の顧客・商品分析プロジェクトです。

「このEC事業を成長させるなら、どこに注目すべきか？」という問いから始めました。

SQLを中心に分析し、AI（Claude）も活用しながら、データの確認、仮説の検証、分析結果の整理まで進めました。SQLのたたき台を作ってもらったり、データをいろいろな角度から見るときに使ったり、チャートやドキュメントを作るときにも使っています。ただ、AIが出した結果をそのまま使ったわけではありません。数字が本当に合っているか、そもそもその分析方法でいいのか、結果をどう解釈するかは自分で確認しました。

## ビジネス上の問い

もし自分がこのEC事業の成長を担当するとしたら、

> **顧客価値を高めるために、どのような顧客行動・商品カテゴリー・セラーに注目すべきか？**

という問いを設定しました。

### まず分かったこと

**完了注文が6件以上ある顧客は全体の約32%ですが、この顧客層だけで実現収益の55.7%を占めていました。**

そこで、

- 購入頻度が高い顧客はどんな人なのか
- 特定の商品やカテゴリーに偏っているのか
- どんなセラーから購入しているのか

を順番に調べていきました。

---

## AIをどう使ったか

今回の分析では、AI（Claude）をかなり使いました。SQLのたたき台作り、データをいろいろな角度から見る作業、検証すべき項目のリストアップ、チャートやドキュメントの作成——このあたりはAIに手伝ってもらうとかなり早く進みます。

ただ、以下は自分で決めました。

- そもそも何を分析するか
- 数字（指標）をどう定義するか
- データが信頼できるか、おかしな前提が混ざっていないか
- どの分析手法を使うか（そして合わなければ却下すること）
- 出てきた結果が何を意味していて、何を意味していないか
- 最終的にどう判断するか

具体的にどういうことか、3つの例で説明します。

### 例1：顧客の分け方

最初は、Recency・Frequency・Monetaryをそれぞれ点数化して足し合わせる、いわゆる標準的なRFMスコアを試しました。ただ分布を見てみると、購入回数（Frequency）は特定の値に偏っていて、五分位で機械的に区切るとグループの意味がぼやけてしまうことが分かりました。さらに、このスコアだと登録したばかりの顧客や一度だけ高額購入した顧客が、本当に何度も買ってくれている顧客と同じ「上位」グループに入ってしまうことにも気づきました。そこで、購入回数の実際の分布をもとに、行動ベースでグループを分け直しました。

これは「AIが間違えていた」という話ではありません。両方の案を素早く形にしてくれたのはAIですが、どちらが実際のデータやビジネスの問いに合っているかを判断したのは自分です。

### 例2：FBSとStandard、セラーの違い

最初に単純比較したとき、Standardのセラーの方がFBSのセラーよりずっと実現収益が高く見えました。でも、そのまま結論にする前に「他の条件は同じか」を確認したところ、FBSのセラーは1社あたり16商品、Standardのセラーは28商品と、扱っている商品数が最初から違うことが分かりました。これでは実現収益の差が本当にロジスティクスの違いによるものか分かりません。そこで商品1つあたりの実現収益に直してみると、差はほぼ消えました（約634千バーツ vs 約624千バーツ）。

これは面接で一番話したい例です。最初の数字だけ見ると「Standardの方が優れている」と言いたくなりますが、その前にデータの構造を確認したことで、間違った結論を避けられました。

### 例3：Electronicsのリピート率

Electronicsは、カテゴリー内でのリピート率がHomeより低く（41.1% vs 75.5%）、最初は「リピートされていない＝問題があるのでは」と思いました。でも実際にElectronicsを買っている人たちを見てみると、全体としての購入頻度も金額もHome購入者より高く、カテゴリー内での購入間隔が長いことが分かりました。そこで、この数字だけを見て「リピートされていない＝問題がある」とは判断しませんでした。

## Dataset

**Shopee Thailand** の取引データ（合成データ）を使っています。期間は2022年〜2025年の約4年分です。あくまで1つのプラットフォームのデータなので、タイのEC市場全体の話としては読めません。

| データ | 件数 |
|---|---:|
| 顧客 | 60,000 |
| 注文 | 300,000 |
| 完了注文のある顧客 | 55,822 |
| セラー | 200 |
| 対象期間 | 2022年〜2025年 |

使ったのは顧客・注文・注文明細・商品・セラーの5つのテーブルです。

### 「売上」って何を指す？

分析を始める前に、どの金額を「売上」として使うかを確認しました。`orders.total_amount` には、後でキャンセルや返金になった商品も含まれていて、実際に確定した金額とは違うことが分かりました。なので、この分析では **完了（Completed）した注文明細だけ** を実現収益として扱っています。

## どう進めたか

1. まずデータを確認して、「実現収益」をどう定義するか決める
2. 購買行動をもとに顧客を分ける
3. 購入頻度と顧客価値の関係を見る
4. カテゴリー・商品ごとの買われ方を見る
5. セラーの特性ごとの違いを見る
6. 比較する前に、他の条件が違っていないかも確認する
7. 最後に、分析結果から何ができるかを考える

# 1. 顧客分析

## どうやって顧客を分けたか

最初は標準的なRFMスコアを試しましたが、テストしてみると新規顧客や一度だけの高額購入者が、本当に繰り返し買ってくれている顧客と混ざってしまう問題がありました（上の「例1」参照）。なので、購入頻度・recency・登録してからの期間・一度きりか繰り返しかを見て、ルールベースで分け直しました。登録したばかりの顧客は、まだ様子を見る期間が短いだけなので、既存顧客とは分けて扱っています。

### 一番はっきりしたこと

**一番はっきりしたのは、購入頻度と顧客価値の関係でした。**

完了注文が6件以上ある顧客は全体の約32%ですが、実現収益の55.7%を占めていました。

購入頻度が上がるほど、1人あたりの平均実現収益も一貫して上がっていきます。

| 完了注文数 | 平均実現収益／顧客 |
|---:|---:|
| 1 | ฿12,366 |
| 2〜3 | ฿30,521 |
| 4〜5 | ฿54,227 |
| 6〜8 | ฿83,616 |
| 9以上 | ฿124,741 |

一部の層だけが飛び抜けているのではなく、どの段階でも順番に上がっていくのが特徴的でした。

---

# 2. カテゴリー・商品分析

次に、価値の高い顧客が特定のカテゴリーや商品に偏っているかを見てみました。

HomeとElectronicsの2カテゴリーで実現収益の約96.2%を占めています。ただ、価値の高い顧客だけが特定のカテゴリーに偏っている、ということはありませんでした。カテゴリー単位でも商品単位（購入者100人以上の商品まで）でも、目立った偏りは見つかりませんでした。

### 分かったこと

**価値の高い顧客だけが、特定のカテゴリーや商品を多く買っているという傾向は見つかりませんでした。**

「価値の高い顧客が好きなカテゴリー」を探すというアプローチは、試す価値のある仮説ではありましたが、このデータではあまり根拠にならなさそうです。

### Electronicsについて

Electronicsはカテゴリー内でのリピート率がHomeより低いですが、「例3」で見たとおり、購入者全体の頻度や金額はHomeより高く、カテゴリー内の購入間隔も長い傾向がありました。そのため、この数字だけでリテンションの問題と判断するのは避けました。

# 3. セラー分析

最後に、セラーの特性が顧客や実現収益と関係あるかを見ました。

## 見落としがちな条件の違い

FBSのセラーとStandardのセラーでは、扱っている商品数がそもそも違いました——FBSは1社あたり16商品、Standardは28商品と、きれいに分かれています（例2参照）。これでは単純に実現収益を比べても意味がないので、商品1つあたりの実現収益で比べ直しました。

| 指標 | FBS | Standard |
|---|---:|---:|
| 実現収益／商品 | ฿634K | ฿624K |

見かけ上あった差は、ほぼなくなりました。

### 分かったこと

**FBSとStandardの実現収益差に見えたものは、実はほとんどが商品数の違いによるものでした。**

一方で、CompanyセラーはIndividualセラーより商品1つ・顧客1人あたりの実現収益が少し高い傾向がありました（それぞれ約18%、約20%高い）。ただしIndividualセラーの方が、購入頻度の高い顧客を集めている傾向もありました。なので、どちらが「良い」セラーとは単純には言えません。

---

# 分かったことのまとめ

### 1. 何を買うかより、どれだけ頻繁に買うか
購入頻度が高い顧客ほど、一貫して実現収益が高い傾向がありました。

### 2. 価値の高い顧客に、特定の好みはなかった
カテゴリーでも商品でも、目立った偏りは見つかりませんでした。

### 3. 単純な数字の比較は、間違った結論につながることがある
FBSとStandardの実現収益差は、商品数の違いをそろえたらほぼ消えました。

### 4. セラーの種類は、単純な優劣では語れない
Companyは効率が良く、Individualは頻繁に買う顧客を集めている、という違いがありました。

# やった方がいいと思うこと

## 1. 購入頻度を上げる施策を優先する

特定のカテゴリーを推すより、たまに買う・時々買う顧客の購入頻度を上げる方が効果がありそうです。購入後のフォローや、リピートを促す仕組み、過去の購入に合わせたお知らせなどが考えられます。実際に効くかどうかは、思い込みではなく試して確かめる必要があります。

## 2. 離れかけている優良顧客には、個別に声をかける

過去に何度も買ってくれていたのに、180日以上購入がない顧客が547人いました（全体の0.98%、過去の合計金額は約4,820万バーツ）。人数はそれほど多くないので、全員に同じキャンペーンを送るより、個別に声をかける方が合っていると思います。

## 3. Companyセラーがなぜ効率が良いのか調べる

CompanyとIndividualの差は気になる大きさですが、これだけでセラー構成を変えるほどの根拠にはまだなりません。価格の付け方や商品ページの見せ方、在庫、配送、接客など、運営面で何か違いがあるか調べてみる価値はあります。

## 4. FBSとStandardの生の実現収益で判断しない

この差は商品数の違いから来ているだけでした。ロジスティクスまわりを判断するときは、この数字を根拠にしない方がいいです。

# 限界

この分析は「関連性」を見ているだけで、「因果関係」を証明したものではありません。たとえば、購入頻度を上げれば必ず実現収益が増える、というところまでは言えません。

顧客のグループ分けも、このプロジェクトのために自分で作った基準であって、既存のCRMのセグメントではありません。

データも合成データですし、Shopee Thailandという1つのプラットフォームの話なので、タイのEC市場全体の話としては読めません。商品単位の一部データは値のばらつきが少ないところもあるので、商品レベルの話は少し慎重に見た方がいいと思います。

ここで挙げた施策が本当に効くかどうかは、実験データや追加の運用データがないと確認できません。

# まとめ

このデータから見えてきたのは、特定のカテゴリーやロジスティクスの仕組みより、**すでにリピート購入している顧客の購入頻度をさらに高めることを、まず検討すべきだ**ということでした。

このプロジェクトを通して伝えたいのは、分析の進め方そのものです。SQLのたたき台やデータの探索、グラフ作成といった手を動かす部分はAIにかなり任せていますが、何を分析するか、その結果を信じていいか、最終的にどう判断するかは自分で決めています。最初に出てきた数字をそのまま受け入れるのではなく、一度立ち止まって確認してから動く——そういう働き方をこのプロジェクトで示せていたらと思います。
